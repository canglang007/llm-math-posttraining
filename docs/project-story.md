# 一页纸：LLM Math Post-Training（面试/简历版）

> 更新时间：2026-11-19 20:00（Asia/Shanghai UTC+8）

## 一句话

**在 Qwen3-4B + GSM8K 上，把"后训练数据引擎"做成可量化实验：11 个模型档位、1319 题 test 终评、每步配对显著性检验，并如实报告 8/9 个方法对比不显著。**

## 我做了什么

1. **建数据引擎**：官方 CoT 做 SFT（格式地基）→ 模型自采样 + **答案验证**做 RFT → 用验证器产出的偏好对做 DPO → 在线采样 + 规则奖励做 GRPO。
2. **做可归因的消融**：A2 对照组与 E2b 处理组同起点、同超参、同题量（286 题），**唯一差别是那 37 条（12.9%）错误解是否被过滤**。
3. **换推理引擎前先校准口径**：HF 4bit 与 vLLM bf16 逐题一致率 84.5%，拆解后确认主因是 4bit 量化噪声（同精度两引擎 96.7%），据此把 test 评测迁到 vLLM bf16——1319 题从 15 小时压到 3 分钟/模型。
4. **做失败分析**：把分数拆成「抽取失败率 × 可解析题正确率」，并人工判读分叉题，定位错误机制。

## 结果（test 1319，vLLM bf16 口径）

| 对比 | 数字 | 显著性 |
|---|---|---|
| Base → SFT | 0.7604 → 0.8112，**+5.08pt** | **p=0.0002** |
| RFT 验证 vs 不验证（A2 消融） | 0.8120 vs 0.7945，**+1.74pt** | **p=0.022** |
| 其余 8 个方法 vs SFT | −1.0 ~ +0.91pt | p≥0.23，均不显著 |

## 三个可以讲深的洞察

**① SFT 提升的不是算术，是"会收尾"。** Base 在可解析题上正确率 0.8767（比 SFT 还高），但 13.3% 的题没输出 `####`。SFT 把可解析率从 86.7% 拉到 99.8%，分数随之 +5.08pt。**格式地基价值可量化。**

**② 数据里的错，模型会照学。** 不经验证的采样数据只含 12.9% 错误解，就让 test 掉 1.74pt（p=0.022）；
分叉题的错误形态与训练错解同源（局部算术滑落、推理结构正确）。**验证器不是可选组件。**

**③ 1pt 级效应只有大数据集能判。** 同一个 A2 对比，dev-200 上 p=1.000（判不出），test 1319 上 p=0.022（显著）。
**这解释了为什么很多"方法涨点"的结论不可靠。**

## 技术要点（可被追问的部分）

- **口径工程**：双后端（HF 4bit / vLLM bf16）共存，prompt、停止词、答案截断完全共用；
  `--backend` 切换，`compare_inference_backends.py` 输出判分一致率/答案一致率/翻转明细。
- **统计**：所有对比用 McNemar 配对检验（逐题对齐），报四格与 p 值，不报裸均值差。
- **数据纪律**：test 只评一次、不参与任何选择；自采样数据一律由公开答案验证；`audit_data_integrity.py` 自动巡检泄漏与唯一 id。
- **可复现**：81 个单测（含口径守卫）、配置化训练、所有表格由脚本从预测 jsonl 重算。

## 边界（主动说明，避免被问倒）

- 单模型（4B）× 单数据集（GSM8K），结论不外推到"DPO 无用"；
- 未做多 seed、MATH 跨分布、更大模型——这些是"把结论做宽"，不是"把结论做对"；
- dev 与 test 的结论差异本身是重要发现（见洞察③），不是数据问题。

## 如果面试官问"最有价值的一件事"

不是 0.8203 那个最高分，而是 **A2 消融 + 口径校准这两件事**：
它们把"我训了几个模型"变成"我知道每个数字的可信区间在哪、以及为什么"。

**动词开头 → 具体方法/规模（不留术语）→ 基线到结果的完整数字 → 显著性 → 这个结果说明什么。**

## A. 算法岗版（三条，推荐）

**大模型后训练 · 数学推理数据引擎**｜个人项目｜2026.11
技术栈：PyTorch、transformers、PEFT(LoRA)、TRL、vLLM、GSM8K

- 基于 Qwen3-4B-Base 完成 **SFT / RFT / DPO / GRPO 四类后训练，共训练并评测 11 个 checkpoint**
  （Base、SFT、3 版 RFT、3 版 DPO、2 版 GRPO；LoRA r=8，单卡 16GB 可复现），
  在 **1319 题 GSM8K test 集**上统一评测（greedy、同一 prompt 与判分函数）：
  SFT 将答案可解析率由 **86.7% 提升至 99.8%**，准确率 **76.04% → 81.12%（+5.08pt，McNemar p=0.0002）**，
  是全部方法中唯一显著的大效应。
- 设计**单变量消融**量化"答案验证"的贡献：取同一批 286 条模型自采样解，仅控制"是否用答案验证过滤
  其中 37 条（12.9%）错误解"，起点/超参/题量完全一致；验证组 test **81.20% vs 不验证 79.45%（+1.74pt，p=0.022）**，
  且不验证组同时低于"不训练"的 SFT（−1.67pt），分叉题分析显示错误形态与训练错解同源
  —— 证明**自采样数据不经答案验证会污染模型**。
- 搭建**双后端评测与口径校准流程**：将评测从 HF `generate`（4bit、batch=1）迁移到 **vLLM bf16**，
  单模型 1319 题耗时 **约 5 小时 → 3 分钟**；迁移前实测两口径**逐题一致率仅 84.5%**，
  通过 HF-bf16 / HF-4bit / vLLM-bf16 三方对照定位主因为 **4bit 量化噪声（同精度下两引擎 96.7%）**，
  据此制定"双口径并存、不可混表"的评测规范，避免历史分数与新分数被误比较。

## B. 推理/工程岗版（三条，突出系统能力）

**LLM 推理评测系统 · 数学推理后训练**｜个人项目｜2026.11
技术栈：vLLM、transformers、PEFT、Python、pytest、GitHub Actions 式 CI（本地）

- **将 LLM 评测吞吐提升约 100 倍**：把 1319 题的评测链路从 HF `generate`（4bit、batch=1、约 5 小时/模型）
  迁移到 **vLLM continuous batching + bf16**（约 3 分钟/模型），11 个模型 × 1319 题的完整评测从 15 小时压缩到 34 分钟。
- **解决引擎迁移的可比性问题**：自建 `compare_inference_backends.py` 做逐题一致性校准，实测跨精度一致率
  仅 84.5%，用三方对照（HF-4bit / HF-bf16 / vLLM-bf16）把差异归因到**量化而非引擎**（同精度 96.7%），
  并以 `--backend hf|vllm` + 共享 prompt/停止词/答案截断的设计保证两条链路口径一致。
- **工程保障**：为评测与数据链路补 **84 个单测**（含"口径守卫"、答案判定、数据泄漏审计），
  配置化训练（12GB/24GB 两套）、所有结果表由脚本从逐题 JSONL 重算而非手抄，
  并输出可交互的逐题对比 demo（11 个 checkpoint 分数 + 同题五模型回答）。

## C. 极简版（两行，版面紧张时用）

- 基于 Qwen3-4B 完成 SFT/RFT/DPO/GRPO 共 11 个 checkpoint 的训练与 1319 题 test 端到端评测：
  SFT 准确率 76.04%→81.12%（+5.08pt，p=0.0002）；其余 8 组方法相对 SFT 均不显著（最好 +0.91pt，p=0.230），如实报告负结果。
- 以单变量消融证明答案验证的价值（+1.74pt，p=0.022）；将评测迁移至 vLLM（1319 题 5 小时→3 分钟），
  并用三方对照定位 4bit 量化噪声导致的口径差异（跨精度一致率 84.5%），建立双口径评测规范。
