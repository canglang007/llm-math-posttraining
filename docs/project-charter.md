# 项目章程

更新时间：2026-11-15 07:36（Asia/Shanghai，UTC+08:00）

## 背景

在线教育/企业场景需要私有化的数学推理解题助手：通用大模型 API 成本高、学生数据不能出域、回答格式和稳定性不可控。一个 4B 小模型经过后训练，可以在成本、隐私和可控性上更合适。

**项目首要动机（2026-11-15 用户确认）**：本项目是为找实习面试准备的作品，教育场景是叙事载体，不是交付客户。因此所有工作以「可展示、可复现、能讲清楚」为第一优先：优先产出一条干净的主链路证据（Base → SFT → RFT 的 pass@1 对比）、能单独量化数据引擎贡献的消融、以及失败分析和可演示 demo；实验规模以讲得清为准，不追求刷榜或堆方法。

## 目标

用公开 GSM8K/MATH 数据，构建一条可复现的后训练链路：

```text
公开数据
→ 数据引擎（清洗/去重/难度分层/配比）
→ SFT
→ 拒绝采样（答案验证）
→ DPO（正确/错误解答偏好）
→ 公开 test 评测
→ 失败分析
```

主张：数据过滤和拒绝采样能提升 Qwen3-4B-Base 的数学推理 pass@1；并单独量化数据引擎的贡献。

## 非目标

- 不做 Agent、tool calling、user simulator、benchmark 平台；
- 不做预训练、大规模 RL、生产级服务；
- 不用自造标签当主证据；
- 不先上服务器：先完成本地 foundation 和单测。

## 交付物

- 数据准备脚本和 provenance；
- 答案抽取与 pass@1 评测；
- SFT/RFT/DPO 数据构造与训练脚本；
- Base/Public-SFT/RFT/DPO 结果和失败分析；
- 一个可演示的 CLI/Streamlit 解题助手；
- 面试用 1 分钟叙事和 5 分钟 demo。

## 优先级约束（面试导向）

1. 主线闭环优先：E0 → E1 → E2 必须有可复现数字和同一套评测口径；test 只评一次的规则不因赶时间放宽。
2. 差异化卖点是 A1/A2 消融（单独量化数据引擎贡献），优先级高于 E3/E4。
3. DPO、teacher distill、MATH 全量扩展属于加分项，时间或算力不足时可砍，但不能让主线断在「只有脚本没有结果」。
4. 服务器按需使用：先用 dev 子集（200 题）做 baseline probe 确认 headroom 和答案抽取失败率，再决定训练预算；test 只在最终统一评测时对每个方法各评一次。每次实验记录 seed、配置、硬件和耗时。
5. 每轮实验留下可讲的东西：结果表、失败案例、一张图或一个 demo，避免只有日志。
